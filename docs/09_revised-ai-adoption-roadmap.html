AI活用ロードマップ 2026 / 全体構想

AIとともに、
ソフトウェアと業務を
継続的に進化させる組織へ

本資料は、個人ごとのAI利用を組織の再現可能な成果へ転換するための全体構想である。目指す姿、共通基盤、業務領域ごとの変革、運営・安全性、18か月の進め方を一つの体系として示す。

対象: 開発・運用・データ・知識活用 想定規模: 100名・10チーム・50システム 基準日: 2026年8月25日 更新: 四半期・重大イベントで見直す
目指す成果価値提供を速め、品質・安定性・説明責任を守る
変革する範囲開発・運用・知識・データをつながった流れで変える
進め方灯台業務で実証し、再利用できた仕組みから共通化する
変化への備え統制契約を固定し、モデル・製品は評価で交換する

01

背景と目的 — 個人のAI活用を、組織の成果へ転換する

AIの能力向上を待つだけでは、業務全体の時間・品質・リスクは改善しない。仕事の流れと運営の仕組みを同時に変える

AIの役割が変わった

補完・要約中心の支援から、複数ステップを計画し、コード・データ・業務ツールを扱うエージェントへ用途が広がっている。[11][12]

個人最適だけでは広がらない

チームごとに製品、権限、評価、知識の扱いが分かれると、重複投資と安全性のばらつきが増え、成功が他チームへ再現されない。

共通基盤だけでも価値にならない

基盤機能の整備数ではなく、顧客価値までの時間、人の検証負荷、品質、総コストが実務で改善したかを成果として扱う。[1]

この構想が実現する変化

この構想の目的対象業務で「価値提供までの時間」と「人の検証負荷」を減らしながら、品質・安定性・安全性を悪化させない状態を、複数チームで再現可能にする。

対象とする四つの領域

</>
開発要件理解、設計、実装、テスト、レビュー、移行を一つの流れとして短縮する
△
運用アラートから情報収集、仮説、対処判断、振り返りまでを支援し、復旧を早める
◎
知識・データ根拠付き知識と権限に沿ったデータ活用で、探索と判断の時間を短縮する
◇
共通イネーブルメント評価、ID、Sandbox、接続、標準を提供し、各チームの成功を再利用可能にする

03

目指す姿 — 各チームが安全な経路で、自律的に成果を出す

変化しにくい統制契約を中核に置き、モデル・製品・実装方式は評価で差し替える

変えない中核

  • 事業成果と品質の定義
  • 用途別の責任者・リスク階層
  • ID、最小権限、監査、承認
  • 評価セットと昇格・停止条件
  • 知識の根拠・所有者・鮮度

評価して差し替える周辺

  • 基盤モデルと推論設定
  • コーディング／業務エージェント製品
  • オーケストレーションと長時間ハーネス
  • MCPサーバーと接続方式
  • 価格プラン、実行環境、可観測性製品
04

変革の基本方針 — 成果が確認できた範囲から、自律度を上げる

Anthropicの実装知見とOpenAIの安全設計を、製品非依存の運営原則へ落とす

PRINCIPLE 1
最も単純な解法から始める

検索・テンプレート・決定的自動化で足りるなら、エージェントを使わない。[11]

PRINCIPLE 2
評価してから複雑化する

同じ代表タスクで品質、時間、コスト、失敗を比較し、改善が出た構成だけ昇格。

PRINCIPLE 3
副作用の前で止める

編集、シェル、外部送信、本番操作などの境界で人またはポリシー承認。[12]

PRINCIPLE 4
モデルの進化で引き算する

ハーネスの仮定は陳腐化する。部品を一つずつ外して回帰評価する。[13]

自動化・エージェント化の昇格ラダー

決定的自動化

ルール、SQL、スクリプト、CI。入力と結果が定義可能。

出発点: 再現性が最優先
AI支援

人が操作し、下書き・要約・候補を得る。最終判断は人。

昇格: 修正負荷が許容内
固定ワークフロー

LLMとツールを定義済み経路で接続。各段に検証ゲート。

昇格: 例外が限定的
単一エージェント

計画とツール選択を委任。権限・予算・時間・停止条件を限定。

昇格: 柔軟性の効果を実証
長時間／複数エージェント

分担、並列、評価ループ。隔離環境と独立評価が必須。

限定採用: 増分効果がコストを上回る
三エージェント構成の扱いPlanner／Generator／Evaluatorは有効な候補であって全社標準ではない。Anthropicの2026年実験でも、強いモデルではEvaluatorが不要な負荷になるタスクがあり、約4時間・約125ドルを要した例がある。タスク境界に応じて採否を決める。[13]
05

全体アーキテクチャ — 業務の変革を、共通能力が横断して支える

AIを単体ツールとして配置せず、開発・運用・知識の仕事の流れと、全社共通の安全・評価・再利用をつなぐ

業務領域ごとの変革像

開発 — 意図から安全な変更へ

要件・制約 → 計画 → 実装 → テスト → PR → 学習

人の責任: 目的、設計上の判断、重要差分のレビュー、リリース判断。AIは調査・下書き・反復・検証を担う。

運用 — 検知から復旧と学習へ

Alert → 文脈収集 → 仮説 → 対処案 → 承認 → 振り返り

人の責任: 影響判断と復旧操作。初期は読み取り専用とし、書き込みは個別の安全性評価を通す。

知識・データ — 根拠から判断へ

Event / Data → 根拠 → 検証 → 確定知識 → 検索・判断

人の責任: 正しさ、公開範囲、更新責任。AIは下書き・関連付け・検索を担い、根拠へ戻れるようにする。

契約・保持

学習利用、通常保持、ZDR適用範囲、サポート時アクセス、削除、第三者MCPの条件を機能単位で確認。

データフロー

実行・持ち出し

ファイル読取、ネットワーク出口、資格情報、クリップボード、MCP応答を制御。Prompt Injectionを前提に最小権限化。

07

知識活用 — AI生成物ではなく、根拠と責任を持つ知識を増やす

作成作業は自動化するが、正しさ・公開範囲・更新責任を自動化しきったとはみなさない

1. EventPR、障害、設計決定、問い合わせ
2. DraftAIが変更点・判断・FAQを下書き
3. Evidenceコミット、ログ、原文URLを関連付け
4. Validate矛盾、権限、機密、再現性を検査
5. Approve名前のある所有者が確定
6. Refresh期限・変更イベントで再検証

知識単位の必須メタデータ

根拠、作成・確認者、対象システム、公開範囲、確信度、有効期限、最終確認日。

検索品質の評価

代表質問、正解根拠、取得精度、引用一致、アクセス違反、回答不能時の停止を評価。

Source of Truth

コード、構成管理、チケットなど本来の正を維持。生成文書は根拠への案内・説明層として扱う。

実例からの教訓Uber Genieは参照情報を事前選定し、回答に根拠URLを付ける設計でも、有用回答率は48.9%だった。「人の追加作業ゼロ」ではなく、「記述負荷を自動化し、確定責任を軽量に残す」を目標にする。[10]

最初の90日 — 構想を実行へ移し、3つの灯台で成立性を確かめる

業務成果のベースライン、最小の共通能力、実務での評価を一続きで進め、次の投資判断に必要な証拠を揃える

0〜2週 — 焦点を定める

Sponsor・成果責任者 → 3つの灯台業務 → 現状ベースライン
  • 開発、読取運用、知識から実業務を選定
  • 時間、品質、人の検証、総コストを計測
  • 責任者、利用者、対象データ、失敗影響を登録

3〜6週 — 守りと測定を作る

評価セット → Sandbox・ID → 監査 → 製品比較
  • 代表タスクと正解・非劣化条件を定義
  • 最小権限、隔離、ログ、承認点を実装
  • 候補製品を同じタスク・同じデータ条件で比較

7〜12週 — 実務で検証する

灯台を実行 → 週次評価 → 失敗分類 → Gate判定
  • 成果、修正・検証時間、品質、事故、総コストを測定
  • 現場の失敗を共通標準と評価セットへ戻す
  • 継続、修正、停止とPhase 2の投資範囲を決定

90日目に揃える成果物

1
3つのEvaluation Cardベースライン、代表タスク、結果、限界、人の負荷、総コスト
2
安全性の実装証拠ユースケース台帳、データフロー、権限、監査、承認、停止手順
3
再利用候補複数業務で使えた評価、Sandbox、標準、スキル、知識パターン
4
次の投資判断継続・修正・停止、対象チーム、必要FTE、予算、移行・退出案

開始時に合意する六つのこと

目標状態と対象範囲

North Star、品質の非劣化条件、初期対象の業務・システム・利用者。

灯台ユースケースと責任者

開発、読取運用、知識の3系統から実業務を選び、成果責任者を置く。

Phase 0の人員・予算

6週間の専任枠、製品比較、Sandbox、ログ、Eval実行の暫定予算。

リスク許容と初期権限

R0〜R4、Fast-Track対象、禁止データ、本番書込を許可しない初期線。

Gate判定者と証拠

G0〜G3で誰が、どの実測値と残余リスクを見て継続・停止するか。

共同所有と運営能力

AI Enablement、Platform、Security、Data、SRE、各チームのRACI。

90日目のGate3つの灯台それぞれで、事業・提供成果の改善、品質の非劣化、重大事故の不在、運営可能な総コストを証拠で確認する。成立しない灯台は正常に修正・停止し、再現可能だった共通能力だけを次段階へ投資する。
