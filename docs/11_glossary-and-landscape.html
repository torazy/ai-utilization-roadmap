用語・モデル・最新機能ガイド — AI駆動開発の共通言語

企画書・詳細シリーズで使う用語（ハーネス、スキル、フック、コンテキスト、トークン、〜エンジニアリング）を製品に依存しない形で説明し、2026年10月時点の主要モデルと主要ツールの機能を同じ尺度で並べる。初めて読む関係者が、製品名を知らなくても議論に参加できる状態になることを目的とする。

調査基準日: 2026年10月7日 ／ 製品情報は更新型のため、導入判断時に一次資料で再確認する。

1. 全体像 — 設計の対象が「依頼文」から「仕組み」へ広がった

生成AIの活用は、何を書くか（プロンプト）から、AIが何を見るか（コンテキスト）、AIが働く環境（ハーネス）、AIを動かし続ける仕組み（ループ）、複数のループの連携（グラフ）へと、設計の対象が一段ずつ外側に広がってきた。この進化はどのベンダーの製品を使っても同じで、各層は内側の層を含む。業務の多くはハーネスとループの層で十分な成果が出る。

① プロンプト依頼文の書き方。1回の指示の精度
→
② コンテキストAIに見せる情報の選び方。文書・履歴・ツール定義
→
③ ハーネスAIが働く環境。ツール・権限・検証・記憶
→
④ ループAIを自動で回す仕組み。トリガー・停止条件・評価
→
⑤ グラフ役割の異なる複数ループの連携。受け渡し・分岐

設計対象が外側へ広がる順。各層は内側を含む

① プロンプト
エンジニアリング2022〜
設計するもの: 指示文の構造・言い回し・例示。限界: 指示が完璧でも、AIが見ている資料が違えば結果は違う。当社の対応: L1教育（企画書5章）。
② コンテキスト
エンジニアリング2025〜
設計するもの: コンテキストウィンドウに入る全情報の構成。システム指示・設計書・会話履歴・ツール定義・取得データ。原則: 入れるトークン一つひとつに目的がある状態を保つ。当社の対応: ②ハーネスの作業指示書、③ナレッジ基盤。
③ ハーネス
エンジニアリング2026〜
設計するもの: モデルを包む環境。ツール、実行環境、権限、検証（テスト・CI）、記憶、観測。「エージェント＝モデル＋ハーネス」。特徴: モデルやツールを入れ替えても資産として残る。当社の対応: ②標準ハーネステンプレート。
④ ループ
エンジニアリング2026〜
設計するもの: 人が毎回指示する代わりに、AIを起動し続ける仕組み。トリガー、指示の自動生成、評価、停止条件、コスト上限。当社の対応: ループ詳説、⑦ウォッチループ。
⑤ グラフ
エンジニアリング2026〜
設計するもの: 役割の異なるエージェント・ツール・人の判断を、ノードと辺で明示した実行グラフ。受け渡し規約と分岐。注意: 大半の業務は単一のループで足りる。当社の対応: Phase 3以降の検討対象（自律ループの連結）。
POINT 企画書の「ハーネス→ループ」という方針は、この進化の③と④に投資するという意味である。モデル（AI本体）とツール（エージェント製品）の選定は①〜⑤とは別の意思決定で、ハーネスとループは、モデルやツールを入れ替えても残る組織資産になる。

2. 基本用語 — まずこの12語

各用語の「製品での呼び名」は、GitHub Copilot／OpenAI Codex／Anthropic Claude Code／Google Antigravityの順に示す。4製品とも概念はほぼ共通で、名称と設定ファイルの置き場所が異なる。

AI駆動開発AI-driven development

AIエージェントが調査・実装・テスト・文書化を実行し、人は目的の設定、環境の整備、成果の検収を担う開発の進め方。「AIに補完してもらう」段階と区別する。

当社では: 「エージェントと対話する人」から「ループを設計し、成果を検収する人」へ（企画書2章）。

エージェントagent

目的に応じて情報を読み、ツールを使い、複数の処理を自律的に進めるAIの実行主体。エージェント＝モデル＋ハーネス。同じモデルでもハーネスが違えば別のエージェントになる。

製品例: Copilot coding agent／Codex／Claude Code／Antigravity。いずれも複数社のモデルを切り替えられる製品が増えた。

モデルmodel / LLM

文章やコードを生成するAI本体。各社が能力・速度・価格の異なる複数の種類（ティア）を提供し、タスクに応じて選ぶ（5章）。モデルとエージェント製品は別の選択。

例: GPT-6 Sol／Claude Opus 5.5／Gemini 3.5 Flash／DeepSeek V4（オープンウェイト）。

トークンtoken

モデルが文章を扱う最小単位。日本語はおおむね1〜2文字で1トークン、英語は1単語が1〜2トークン。利用料金は入力トークン数と出力トークン数で決まる。各社とも「100万トークン（MTok）あたりの単価」で表示する。

目安: 1Mトークン ≒ 英語50〜75万語。設計書1冊が数万トークン。トークナイザーは各社・各世代で異なる。

コンテキスト（ウィンドウ）context window

モデルが1回の推論で参照できる情報の総量（トークン数の上限）。システム指示、会話履歴、読み込んだファイル、ツールの定義と結果がすべてここに入る。

現在: 主要各社のフロンティアモデルは1Mトークン前後が標準。注意: 上限まで入れると性能が落ちる（次項）。

コンテキスト劣化context rot

コンテキストに入れる情報が増えるほど、必要な情報を正確に取り出す力が下がる現象。上限のはるか手前から非線形に悪化する（各社18モデルで実測）。

対策: 必要時取得（just-in-time）、圧縮（compaction）、外部メモ、サブエージェントによる分離。

圧縮compaction

長い会話を要約して置き換え、コンテキストを空ける操作。主要なエージェント製品は自動で行い、各社のAPIにも会話途中の圧縮機能が入り始めた。

設計: まず取りこぼしを無くし（再現率）、次に不要情報を削る（精度）。

作業指示書AGENTS.md ほか

リポジトリに置く、エージェント向けの常時読み込み指示。ビルド・テストのコマンド、規約、触ってよい領域、完了条件。短く保ち（目安200行以内）、詳細はスキルや領域別ルールへ分ける。

製品での呼び名: AGENTS.md（Codex・Copilot・Antigravityが読む共通形式）／copilot-instructions.md（Copilot）／CLAUDE.md（Claude Code）。AGENTS.mdの採用数がCLAUDE.mdを上回った（2026年9月調査）。

スキルskill

再利用できる手順・知識・参照資料をMarkdownで束ねたもの。必要なときだけ読み込まれ（遅延ロード）、人が名前で呼ぶか、AIが説明文から判断して使う。

現在: Agent Skillsとして公開標準化（SKILL.md形式、2025年12月）。Copilot、Codex、Claude Code、Antigravity、Cursorなど30以上のツールが同じ形式を読む。

フックhook

エージェントのライフサイクル上の決まった時点（ツール実行の前後、セッション開始・終了、圧縮前など）で、必ず実行されるスクリプトや外部呼び出し。AIの判断を介さない。

使い分け: 「毎回必ず」はフック、「判断を伴う手順」はスキル。製品: 4製品すべてにある（Copilot Hooks／Codex Hooks／Claude Code hooks／Antigravity Hooks）。

サブエージェントsubagent

親エージェントが起動する、独立したコンテキストを持つ作業者。大量のファイルを読む調査や、生成と評価の分離に使う。親には要約だけが戻る。

製品: Copilot subagents／Codex subagents（.codex/agents）／Claude Code subagents／Antigravity subagents。発展形として複数エージェントの協調（Agent Teams、動的ワークフロー、Symphony）。

MCPModel Context Protocol

エージェントが外部サービス（DB、チケット、監視、社内API）のツールやデータを使うための業界標準プロトコル。サーバーを1本立てると、対応する全エージェントから使える。

当社では: ④MCPゲートウェイで接続先を統制。最新仕様は2026-07-28版で、AWS・Databricks・各エージェント製品が対応済み。

5. モデルの種類 — 2026年10月時点の主要モデルを同じ尺度で

各社とも「最上位（高価・遅い・最も賢い）／標準（主力）／軽量（安い・速い）」の3〜4ティアを持つ。選び方は共通で、標準ティアを既定にし、評価が届かない作業だけ最上位へ、採点・分類・大量処理は軽量へ寄せる。コンテキストは各社とも1Mトークン前後が標準になった。

7. 当社企画への含意 — 変わらない軸と、更新する部分

変わらない軸

  • 可搬性のある抽象への投資: スキル（SKILL.md公開標準）、MCP（業界標準）、AGENTS.md（ツール横断）は、この半年でさらに標準化が進み、4製品すべてが読む。
  • モデルとハーネスの分離: Copilot・Databricks・AWSのいずれも「モデルは選択式、統制は基盤側」の構造になった。製品側も他社モデルを載せる。
  • 守らせたい規則はフックとCIへ: 実測でも「指示書だけ」のハーネスは効果が薄い。4製品すべてにフックがある。

更新する部分

  • ループの実行基盤の選択肢が増えた: Copilot定期実行、Codex Automations／Symphony、Claude Code Routines／Managed Agents、AgentCore harness。検討項目D-3で同じ軸（実行場所、予算上限、イベント起動、閉域）で比較する。
  • コストの前提: Copilotは「AI Credits（席料金に含有分あり）」、API利用は「標準ティアの値下がり」「キャッシュ・バッチ・ティア分け」で見積もる。
  • ゲートウェイの実装: Unity Gateway CLI により、開発者端末のエージェント（Claude Code／Codex）を統制経路に乗せる手順が標準化された。
  • 観測: 各製品の管理ダッシュボードが充実したため、⑤ダッシュボードの自作範囲は「ツール横断の統合」に絞る。
